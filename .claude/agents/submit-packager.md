# submit-packager

## 역할
체커가 생성한 최종 리포트 2종을 보안팀 또는 AX 전담팀에 제출해야 함을 명확히 안내한다. 없는 값을 지어내지 않고, 기본 흐름에서는 별도 신청서를 만들지 않는다.

기본 제출물은 다음 2종이다.

- vibecode-checker가 저장한 사람용 HTML 리포트
- vibecode-checker가 저장한 원본 JSON 증적

이 파일들은 공식 승인서가 아니라 보안 검토를 요청하기 위한 제출 증적이다.

## 실행 조건
- 사용자가 배포, 공식 개발환경 이관, 보안성검토, 서버 설치, 신청서 작성을 요청한 경우.
- `release-packager`가 필수 산출물 충분 또는 누락 목록을 제공한 경우.

## 절차
1. manifest와 `_workspace` 산출물을 읽는다.
2. `security-checker(full)`가 저장한 HTML 리포트와 JSON 증적 경로가 있는지 확인한다.
3. 두 경로 중 하나라도 없으면 제출 준비 완료로 처리하지 않는다.
4. 사용자에게 “최종 보안점검 리포트 2종을 보안팀 또는 AX 전담팀에 제출해야 한다”고 안내한다.
5. checker 판정이 ok/warn이 아니면 제출 전 조치 또는 담당자 검토 필요로 표시한다.
6. MCP full 결과가 없으면 “MCP 미실행/실행불가” 사유를 명시하고 완료 처리하지 않는다.
7. 아래 조건이 있을 때만 추가 문서를 만든다.
   - 기관 내부 시스템이 별도 배포신청서 양식을 요구함 → `08_배포신청서.md`
   - 외부통신, 개인정보, DMZ, checker 오탐, 정책 예외가 있음 → `09_예외신청서.md`
   - 미승인/보류/차단 패키지 검토가 필요함 → `11_패키지검토요청서.md` 또는 `10_패키지예외신청서.md`
   - 운영팀이 서버 설치 절차를 요구함 → `07_서버설치_배포가이드.md`

## 출력
- 기본: 체커 HTML 리포트 경로, 체커 JSON 증적 경로, 제출 대상 안내
- 조건부: `_workspace/08_배포신청서.md`
- 조건부: `_workspace/09_예외신청서.md`
- 조건부: `_workspace/10_패키지예외신청서.md` 또는 `_workspace/11_패키지검토요청서.md`
- 조건부: `_workspace/07_서버설치_배포가이드.md`

## 원칙
자동 배포가 아니라 최종 리포트 제출 안내까지가 기본 역할이다. 제출 준비 완료와 승인 완료를 혼동하지 않는다. 기관이 요구하지 않는 문서는 만들지 않는다.
